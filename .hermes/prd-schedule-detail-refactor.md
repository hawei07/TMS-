# 课表排课详情弹窗功能重构 PRD

> **版本**: v1.0 | **日期**: 2026-07-08 | **作者**: Product Manager
> **项目**: D:\market-system-php\ (TMS管理系统)
> **技术栈**: PHP 8.4 + MySQL 8.4 + Vanilla JS, 单文件架构

---

## 1. 概述

### 1.1 背景

课表页面（周视图/月视图）点击班级格子 → 弹出排课详情弹窗 (`showScheduleDetail`，main.js ~9841 行)。当前弹窗功能为：

| 功能 | 当前状态 | 问题 |
|------|---------|------|
| 查看排课信息 | ✅ 可用 | 展示字段：班级、老师、教室、课程、校区、时间段 |
| 查看班级按钮 | ✅ 可用 | 关闭弹窗 → 切换到班级面板 |
| 📋 考勤按钮 | ❌ 形同虚设 | 关闭弹窗 → 切换班级面板 + toast "请去班级列表操作" |
| 删除课次按钮 | ⚠️ 基本可用 | 确认文案只含班级名，不含日期/时段；月视图可能缺 `class_id` |

### 1.2 目标

将排课详情弹窗从「信息查看 + 半成品操作」升级为完整的**操作入口**，支持：

1. **直接在弹窗中操作考勤** — 无需跳转到班级列表
2. **增强删除课次** — 确认信息更完整，安全二次确认
3. **新增调整时间** — 快速修改该排课时段，无需进入编辑排课表单
4. **修复月视图 class_id 缺失** — 确保所有视图下操作按钮可用

### 1.3 非目标

- 不改变课表页面的整体布局或渲染逻辑
- 不涉及拖拽排课功能
- 不改变 `class_attendance` 表结构

## 2. 现状分析

### 2.1 数据流

```
PHP: get_schedule_view
  └─ SQL: schedules s JOIN classes c JOIN courses co
     └─ 构建 grid[day].slots[] / dateSlots[date][]
        └─ JSON → 前端

JS: showScheduleDetail(s)
  └─ s = { schedule_id, class_id?, class_name, course_name, teacher, classroom, campus, start, end, course_id, student_count }
  └─ 渲染弹窗 + 3 个操作按钮
```

### 2.2 已发现缺陷

| # | 缺陷 | 位置 | 影响 |
|---|------|------|------|
| B1 | **月视图数据缺少 `class_id`** | `index.php` ~5277 行 `dateSlots` 构建 | 月视图弹窗中"查看班级"和"考勤"按钮不显示（因 `if (s.class_id)` 守卫） |
| B2 | **考勤按钮无效** | `takeAttendanceFromSchedule` (main.js ~9824) | 只切换面板+toast，不执行任何考勤操作 |
| B3 | **删除确认信息不全** | `deleteScheduleEntry` (main.js ~9830) | 仅显示班级名，无日期/时段，误删风险高 |
| B4 | **无调整时间入口** | 不存在 | 用户需退出弹窗→打开班级面板→编辑排课，路径冗长 |

### 2.3 月度视图 `class_id` 缺失详情

**根因**：`index.php` 第 5276-5287 行，月视图的 `dateSlots` 数组构建时，**漏写了 `'class_id' => $sch['class_id']`**，而周视图第 5364-5376 行正确包含了该字段。

```php
// 月视图（~5277）- ❌ 缺少 class_id
$dateSlots[$curDate][] = [
    'schedule_id' => $sch['id'],
    // ← 缺 class_id
    'class_name' => $sch['class_name'],
    ...
];

// 周视图（~5365）- ✅ 包含 class_id
$grid[$dayLabel]['slots'][] = [
    'schedule_id' => $sch['id'],
    'class_id' => $sch['class_id'],  // ← 有
    ...
];
```

**影响面**：月视图点击任意格子 → 弹窗只显示信息，操作按钮全部隐藏（因为 `showScheduleDetail` 第 9852 行 `if (s.class_id)` 守卫）。

### 3.1 弹窗信息区重构

**当前展示信息**（6 行平铺）：
```

教室：xxx

**新设计**：分组展示，更清晰的信息层级

```
┌─────────────────────────────────────────┐
│  排课详情                          [✕]  │
├─────────────────────────────────────────┤

│  ┌─ 上课安排 ─────────────────────────┐ │
│  │ 教师：张老师                        │ │

│  │ 时段：10:00 - 12:00                 │ │
│  │ 日期：2026-07-08（周三）※仅月视图   │ │
│  │ 周期：2026-03-01 至 2026-07-31      │ │

**变更点**：
- 新增「学员数」展示（`student_count` 已在数据中）
- 新增「排课周期」展示（需 API 返回 `start_date` / `end_date`）
- 月视图新增「日期」展示（数据中应已有，待确认）
- 操作按钮重新设计：考勤、调整时间、删除（三按钮等宽排列，删除为危险色）

### 3.2 操作一：考勤（核心新增）

#### 3.2.1 交互流程

```
点击「📋 操作考勤」
  → 弹窗内容区切换为考勤操作界面
  → 调 get_class_attendance API（传 class_id + schedule_id + session_date）
  → 展示学员考勤列表（inline 编辑，与班级面板中样式一致）
  → 用户修改考勤状态（出勤/缺勤/请假）+ 保存
  → 保存成功 toast "考勤已保存"
  → "返回详情"按钮回到详情页
```

#### 3.2.2 技术要点

| 要点 | 说明 |
|------|------|
| API 复用 | 使用现有 `get_class_attendance` 和 `save_class_attendance` API |
| 弹窗内切换 | 弹窗保留，内容区 `innerHTML` 替换为考勤界面；提供"← 返回详情"按钮 |
| session_date 取值 | 周视图：当前 grid 的日期；月视图：具体点击的日期（需传入 `s.date`） |
| 弹窗宽度 | 考勤列表需适当加宽弹窗（`max-width: 600px`），容纳多列学员状态 |
| 考勤状态 | 出勤/缺勤/请假（与现有系统一致），缺勤时需弹确认检查退费状态（陷阱 #101） |

#### 3.2.3 考勤界面设计

```

│  操作考勤 — 奥数提高班                    [✕] │
│  2026-07-08（周三）10:00-12:00                │

```

### 3.3 操作二：调整时间（新增）

#### 3.3.1 交互流程

```
点击「🕐 调整时间」
  → 弹窗内容区切换为「快速调整时间」表单
  → 预填当前 schedules 记录的值：
      - 上课周期（start_date, end_date）- 日期选择器
      - 星期（weekdays）- 多选按钮
      - 时段（time_slots）- 时段编辑器
      - 教师（teacher）- 搜索下拉
      - 教室（classroom）- 下拉选择
  → 用户修改 → 点击「保存」
  → 调用 update_schedule API
  → 成功后 toast + 关闭弹窗 + 刷新课表
```

#### 3.3.2 与现有编辑排课的区别

| 维度 | 现有「编辑排课」(showScheduleForm) | 新「调整时间」(弹窗内) |
|------|-----------------------------------|----------------------|
| 触发 | 班级面板内点击编辑 | 课表弹窗内直接点击 |
| 模态 | 全屏 modal | 弹窗内嵌表单 |
| 字段 | 全量（rule_type + 日期 + 星期 + 时段 + 教师 + 教室 + 节假日） | 精简（日期 + 星期 + 时段 + 教师 + 教室） |
| 场景 | 完整排课配置 | 快速微调 |

#### 3.3.3 表单设计

```
┌───────────────────────────────────────────────┐
│  调整排课时间                              [✕]│
├───────────────────────────────────────────────┤
│  上课周期：                                   │
│  [2026-03-01] 至 [2026-07-31]  📅            │
│                                               │
│  上课星期：                                   │
│  [周一] [周二] [周三✓] [周四] [周五] [周六]    │
│                                               │
│  上课时段：                                   │
│  ┌─ 10:00 - 12:00 ─────────────────── [✕] ┐  │
│  │ [+ 添加时段]                            │  │
│                                               │
│  教师：[张老师          🔍]                   │
│  教室：[301              ▼]                   │
├───────────────────────────────────────────────┤
│  [← 返回详情]                   [💾 保存]     │
└───────────────────────────────────────────────┘
```

**技术要点**：
- 复用现有 `showScheduleForm` 的表单渲染逻辑，但限定在弹窗内
- 需要先调 `get_schedule` API 获取完整 schedules 记录
- `update_schedule` API 已支持部分字段更新（仅发送变更字段）
- 教师下拉需加载 `get_employees` 且过滤 `is_teacher === '是'`
- 教室下拉加载 `list_classrooms` 并按校区过滤

### 3.4 操作三：删除课次（增强）

#### 3.4.1 当前行为

```javascript
showCustomConfirm('确定删除课次「' + className + '」吗？此操作不可恢复。', callback);
```

**问题**：仅显示班级名，无法区分同班级的不同课次。

#### 3.4.2 增强后

```
┌──────────────────────────────────────┐
│  ⚠️ 确认删除课次                      │
│                                      │
│  班级：奥数提高班                     │
│  日期：2026-07-08（周三）※如有       │
│  时段：10:00 - 12:00                 │
│  教师：张老师                        │
│                                      │
│  此操作不可恢复，该排课规则将被删除。  │
│  已产生的考勤记录不会受影响。          │
│                                      │
│      [取消]          [确认删除]      │
└──────────────────────────────────────┘
```

**变更点**：
- 确认文案包含完整课次信息（班级+日期+时段+教师）
- 添加说明：已产生的考勤记录不受影响（`delete_schedule` 只删 `schedules` 表）
- 使用 `showCustomConfirm` 二次确认（现有模式）

#### 3.4.3 `delete_schedule` API 风险提示

当前 API（`index.php` ~5091 行）直接 `DELETE FROM schedules WHERE id=$id`，不检查关联的 `class_attendance` 记录。需评估是否需要在删除前提示「已有 N 条考勤记录」。

## 7. 安全 / 边界条件

### 7.1 考勤操作边界

| 场景 | 处理 |
|------|------|
| 班级无学员 | 考勤界面显示"该班级暂无学员"，隐藏保存按钮 |
| 该排课已有完整考勤记录 | 正常展示，可修改 |
| 考勤出勤→缺勤 | 检查退费状态（陷阱 #101），存在退费中/已退费订单则阻断 |
| 扣课逻辑 | 复用 `save_class_attendance` 的三级优先级扣课逻辑（陷阱 #103） |

### 7.2 调整时间边界

| 场景 | 处理 |
|------|------|
| 修改日期导致已有考勤记录日期不匹配 | 提示"修改排课日期可能影响现有考勤记录"（soft warning，不阻断） |
| 教室冲突 | 不在此弹窗检测（课表刷新后会显示冲突标记） |
| 时段为空 | 保存时校验 `time_slots` 至少一个时段 |

### 7.3 删除边界

| 场景 | 处理 |
|------|------|
| 存在关联考勤记录 | 提示"N 条考勤记录将保留"（当前 DELETE 不影响 class_attendance，只是 schedule_id 悬空） |
| 已删除的 schedule | 不可能发生（弹窗数据来自实时查询） |

### 7.4 月视图兼容

- 月视图 `dateSlots` 数据中必须包含 `date` 字段（具体日期），否则考勤无法定位 session_date
- 月视图格子可能包含多条排课（同一日期多个时段），弹窗以点击的具体条目为准
