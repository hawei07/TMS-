# 09-open-questions.md — 待确认问题

> 版本：v1.0
> 日期：2026-07-16
> 原则：凡是代码中没有明确注释说明业务意图的、或存在多种合理解释的，都列为待确认。不得将代码中的现有行为自动认定为正确业务规则。

---

## 严重级别定义

| 级别 | 含义 | 处理要求 |
|------|------|----------|
| **P0** | 不确认不能设计领域模型 | 必须在领域建模阶段（DDD 战略设计）前完成确认 |
| **P1** | 不确认不能实现对应流程 | 必须在对应功能开发前（Sprint 启动前）完成确认 |
| **P2** | 可用默认方案，上线前必须确认 | 可先用合理默认方案开发，UAT 阶段必须确认并修正 |

## P0 — 不确认不能设计领域模型

### P0-001: 多校区学员归属模型

| 项目 | 内容 |
|------|------|
| **问题描述** | 一个学员是否可以在多个校区同时就读？如果转校后，学员的"主校区"如何确定？学员的账户余额是跨校区共享还是校区隔离？ |
| **涉及功能** | 学员建档、转校、账户余额、订单校区归属 |
| **相关代码位置** | students 表无 campus_id 字段；orders.campus_id 存在；transfer_records 跨校区转移 |
| **建议方案** | A) 学员绑定单一主校区，转校后主校区切换，账户余额跟随学员跨校区；B) 学员可同时就读多校区，账户余额按校区隔离 |
| **影响范围** | identity-access 领域模型、wallet-ledger 领域模型、转校流程、所有查询的数据范围隔离 |

### P0-002: 校区组织架构层级

| 项目 | 内容 |
|------|------|
| **问题描述** | organizations 表支持树形结构，但代码中未见深层父子递归查询。实际业务场景中组织层级如何定义？大区 → 校区 → 部门？此模型是否支持同一大区内跨校区数据汇总？ |
| **涉及功能** | 组织管理、数据范围、校区统计 |
| **相关代码位置** | organizations 表；api/organizations.php 4 个 action |
| **建议方案** | 支持 3 级树形：大区(Region) → 校区(Campus) → 部门(Department)。数据范围支持"本校区及下属"。 |
| **影响范围** | organization-campus 领域模型、所有业务模块的数据范围隔离 |

### P0-004: 订单与权益的领域边界

| 项目 | 内容 |
|------|------|
| **问题描述** | orders 表承载 6 种业务语义（新报/续费/扩科/小课包/赠送/活动报名/储值/画具销售），这是否应该拆分为独立聚合？特别是储值（wallet）和画具销售（product），它们与课程报名订单的退费/扣课逻辑完全不同。 |
